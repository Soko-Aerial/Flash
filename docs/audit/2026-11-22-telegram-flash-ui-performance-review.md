# Telegram and Flash — UI fluidity, glass and performance review

**2026-11-22 · Static source audit**

Reviewed Flash `dev` at `1b6c4248`, Telegram Android `master` at `21f7d10` (13.2.2 / 7303), and Telegram Desktop `dev` at `c2d0ad9`. The Telegram checkouts are under the sibling `telegram-src` folder. Android is the primary comparison because the requested live glass pipeline is present in the Android source. Desktop contributes separate evidence for history rendering, media and controls. Local source links use the original checkout layout and show the pinned line in the link label. No app builds, installations, device traces or visual side-by-side measurements were performed. Performance impact is a hypothesis until measured.

Telegram's glass depends on capturing the right portion of the scene, downsampling it, caching the result and drawing crisp controls over it. Its other fluidity techniques are independent of glass. They include bounded rendering, stable message identity, anchored transitions, media lifecycles and per-effect budgets. Flash already has shared multiplatform motion tokens, keyed lazy lists, optimistic sending, performance tiers and media fallbacks. The strongest Flash-specific lead is the amount of message-model work the repository does for a draft, progress or reaction update.

Each finding includes source evidence and a Flash action. Proposals require release-build measurement. Build a distinct design with Flash icons, assets, terminology and platform semantics. ## Glassmorphism and visual layering

### GL-01 — Backdrop capture makes the difference

Telegram's glass factories sample actual content from a designated root. In chat the draw source combines the wallpaper underneath with the message and search lists, then supplies separate live and frosted sources. Flash's wallpaper is drawn behind history while the header fills itself with a theme surface. The closest first experiment is a restrained header backdrop, with the icons and text painted sharply above it.
