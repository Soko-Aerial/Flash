## Test-quality findings (all covered by the fix work, not separate IDs)

- No test drives the real `KtorRelayTransport` against the real server (`testApplication` contract test).
- `handleSession` is never run in a test; the fake `WebSocketSession` has infinite, never-failing channels.
- Mailbox/directory tests are single-threaded; `ServerDatabaseTest` checks table existence only (no file DB, WAL, restart, migration).
- `DirectoryRoutesTest` asserts the self-declared `department=dept-gh` works for a stranger; `testTtlExpirationAndSweeper` asserts the buggy past-timestamp expiry.
- No golden vector pins the cert canonical bytes between client and server.
- No test for: sender spoofing, revocation through `Main`, restart persistence, HTML escaping of every sink, CSRF, directory authorisation, concurrent login/enrolment, key-file permissions, oversized frame, handshake timeout, slow consumer, drain above 100 rows.

## Module decision (recommended by the review, to be recorded as an ADR by the foundation work)

1. `:core:hub-protocol` — pure KMP (android + jvm), explicitApi, no Ktor/coroutines/Room: relay frames + codec + error codes, cert types + `RevocationList` + canonical writer + `EnrollmentInvite`, REST DTOs, ONE JSON codec, an `EcdsaVerifier` seam so it does not depend on `:core:security`. Used by BOTH `:server` and the client.
2. `:core:enterprise` — client hub code (relay client/transport, enrolment + directory clients, credentials, trust-store port + adapters, a `HubSession` status manager). `core:messaging` keeps only a small `HubTransport` port it owns. `:server` never depends on `:core:enterprise`.
3. Do NOT merge hub code into `core:network` / `core:engine` / `core:messaging` (the rejected NET-1/ENG-1/MSG-2 pattern); no single `:core:hub` mixing server and client code; do not make `core:security` depend on hub-protocol.
